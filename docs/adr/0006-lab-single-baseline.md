# 0006 只保留 TuningLab 一份实现：实验台升级为唯一基准

## 状态

已接受（2026-11-02）

## 背景

同一套手感规则在仓库里被写了两遍：

- `Assets/Scripts`：正式游戏代码。28 个运行时文件、约 3000 行，玩家是 `PlayerMotor`（1002 行），配 1526 行 NUnit 测试。
- `Assets/TuningLab`：手感调试台 + 关卡管线。玩家是 `LabPlayer`（665 行），配 `TuningLab`（793 行）、关卡数据模型和一个 1558 行的关卡编辑器，**0 行自动测试**。

两边各有一套 `EdgeState` / 红热门槛 / 碰撞结算，谁也不是权威。结果是 PR #17 把 `Assets/Scripts` 整棵删掉时，没人能说清这是"删掉一份草稿"还是"删掉了实现和它全部的测试"。这就是协作问题的根源，不是某一次的失误。

对比之后的事实：

| | 旧 `Assets/Scripts` | 现 `Assets/TuningLab` |
| --- | --- | --- |
| 玩家单体 | 1002 行，动量交换未实现（见 ADR-0004） | 665 行，含 `CaptureDash` / `ApplyDash` 的完整动量互换 |
| 职责切分 | 好：一机制一文件，最小 6 行 | 差：机制只有竖绳一个文件，其余挤在 `TuningLab` |
| 接线方式 | `GameTuning.asset` 外置数值 + 组件订阅 | public 字段手工接线 + 满地 `lab == null` 卫兵 |
| 自动测试 | 1526 行，实测可跑 | 0 行，只有编辑器菜单自检 |
| 内容 | 形态 / 材质 / 生命 / 跨区域存档 | 无 |
| 工具 | 无 | 关卡编辑器 + 分区相机 + 实时调参 HUD + 自检 |

## 决策

**TuningLab 是唯一基准。** 规则的实现只允许存在一份，就在 `Assets/TuningLab`。

选它不是因为它更优雅 —— 它在职责切分和可验证性上明确更差 —— 而是因为**可替代性不对称**：

- 旧侧的优雅是可复制的：机制拆成小类，挂到实验台已有的 `TuningLab.PlayerHit` 和 `LabPlayer.EdgeStateChanged` 事件上就行。
- 实验台的管线是不可复制的：关卡数据模型 + 编辑器 + 自检是策划此刻用来产出关卡的东西，退回旧侧等于让他停摆。

配套约束：

1. **规则文档是上游，代码是下游。** 红热 / 锻造 / 冲刺的对撞语义写在 `docs/冲刺与对撞-现行规则.md` 和 ADR 里，实验台按它实现；不再允许"两份代码互为参考"。
2. **新机制 = 新的小文件**，订阅 `PlayerHit` / `EdgeStateChanged` 来接入，`TuningLab.cs` 不再增长一行。这条是旧侧唯一值得原样继承的优点。
3. **可验证性必须补上**：`Assets/TuningLab` 拆 asmdef，锻造规则按旧侧那 12 条测试移植成实验台的规格，作为第一张回归安全网。
4. 旧侧代码不删历史：`feat/forge-red-hot` 分支保留，作为移植形态 / 材质 / 生命 / 存档时的清单来源。

## 后果

- 形态、材质、生命 / 重生、跨区域存档四组机制在实验台上是 0，要按旧侧清单重建，约 2–3 天。
- 锻造要在 `LabPlayer` 上重做一遍（约 80 行）：边态加 `Spirit`、单一入口 `StrikeEdge`、独立锻造门槛、场景撞击也锻造。
- 拆 asmdef 会牵出实验台的接线问题：`TuningLab.Awake` 里 `autoBuild` 会顺手把整个房间、两个玩家和相机全搭出来，测试必须靠"先禁用 GameObject 再激活"绕开。这是真实成本，写在这里以免后来的人以为是测试写错了。
- 热二再吃一记红热级撞击 = 塌到本体，在旧侧是直接 `PlayerLife.Kill`。实验台暂时没有生命系统，这一步先抛 `EdgeCollapsed` 事件，谁接入谁决定后果；规则本身不因此打折。
- 「撞场景也锻造」在实验台是按碰撞体一律算数的，绳、以后加的材质面都算。v3/v4 撞竖绳必然过红热门槛，等于撞绳免费加热边框 —— 这条要策划拍板，记在现行规则 §6-14。**后续（2026-11-05）已拍板**：绳不算锻造面，只有三级以上的弹回才按红热撞击结算。
- 两边都直接读 `Keyboard.current`，所以纯输入驱动的测试在无头环境仍然跑不了。旧侧那 16 条失败是这个问题，不是新代码的回归。要真正可测，得把输入从玩家身上抽走 —— 那是下一步，不在本 ADR 范围内。
