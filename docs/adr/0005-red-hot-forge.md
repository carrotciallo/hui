# 0005 红热锻造：边框四态、碎边组合决定 A 的形态

> **部分失效（2026-11-06）**：本文"灵体框仍是实体（一整块实心盒）"与"灵体照常参与双人动量交换"两条已被 [ADR-0007](0007-spirit-intangible-timer.md) 取代——灵体现在是无实体、有存在时限、到时即死的穿透态。红热 / 锻造 / 碎边 / 形态组合语义（含"灵体不可复锻"）继续有效。

## 背景

ADR-0004 之后，双人碰撞统一成"动量交换 + 红热"，但红热只是一层描边：热 1 限时 1.5 s、热 2 永久，没有后果，也没接到形态系统上。P5 的形态（大炮 / 转换器 / 攀附 / 木筏 / 空）靠数字键手切，和碰撞完全脱钩，策划要的"锻造"还没有落地。

同时红热只在玩家之间结算：A 自己跳起来砸地面不产生任何状态，而自由落体恰恰是最自然的一锤。

## 决策

- **碰撞等级就是速度等级的读数**：不引入第二套"撞击强度"。沿轴分量落在哪一级，就按哪一级判定，门槛沿用场景 `TuningLab` 组件上的等距门槛（`tierFirstCells` + `tierSpacingCells`）。
- **两条门槛，锻造低于红热**：`forgeTierIndex = 0`（20.00 = 4 格）只砸得碎热二框；`redHotTierIndex = 1`（28.28 = 8 格）才是红热级。代码里强制 `min(forge, redHot)`，配反了也不会出现"碎框比升温难"。
- **边框三态（Hot1 已于 #55 删除）**：`Normal → Hot2（永久）→ Spirit`。热 2 再吃红热级撞击不是"打回热 1"，是碎到本体：塌框。热 2 只吃一级撞击则那条边碎成灵体框。
- **灵体框仍是实体**：边框只是视觉，身体碰撞箱不变（仍是一整块实心盒），所以灵体照常参与双人动量交换；但它不可复锻。
- **场景碰撞走同一条路**：撞地面 / 撞墙在 `OnCollisionEnter2D` 里结一锤，`Vp` 取自己沿"接触法线反方向"的碰撞前分量（静止物件不贡献速度）。只认 Enter，贴着不动不重复锤。
- **形态由碎边的组合决定，不由玩家选择**：碎 1 条 = u 大炮、相邻 2 条 = L 转向器、相对 2 条 = = / ‖ 电梯、只剩 1 条 = 矛（4 种朝向退化成 1 种）、全碎 = 灵体。朝向取最后碎的那条边。
- **形态是碎边掩码的纯函数**：`LabForms.Of(mask)`，不保存状态、不听输入。`LabPlayer.SetEdge` 维护掩码并抛 `FormChanged`；掩码清空（`Teleport`）就回普通形态。这样"哪几条边碎了"是唯一真相，形态不会被手切污染，也方便测试逐个组合断言。
- **本期只做形态切换，不做形态功能**：只有 Issue #15 的 u 大炮接了行为（装填 / 发射），L / 电梯 / 矛 / 灵体仍是读数。
- **复活清账**：`Teleport` = 复活语义，四条边退回常态、形态回普通。灵体不是永久惩罚。

## 后果

- 锻造 + 形态有 23 条 PlayMode 规格（`Assets/TuningLab/Tests/LabForgeTests.cs`：逐级升温、灵体、五种碎边组合、致死、自由落体红热 / 砸碎 / 反例、复活清账）。
- 落地从此有代价：A 带着热 2 的边从 8 格以上摔下来就是死，关卡里"高台 + 红热对撞"的组合要重新检查。
- 实验台没有生命系统，塌框的后果暂时是 `Destroy(gameObject)`，同时相机改绑存活的那名玩家并锁死尺寸。生命系统接上后这条要换成正式的死亡 / 重生流程。
- HUD 多了形态栏（`u 大炮 口朝↑`）和膛内栏，锻造结果不用看代码就能读。

## 待确认

1. **"一级碰撞"取 V0 还是 V1**。Issue 用 1 起的序数，仓库挡位从 `V0` 起算，本文按"一级 = V0 = 4 格 / 20.00"实现；若指 V1，锻造门槛与红热门槛重合，"砸碎"和"砸死"就是同一锤。
2. **灵体可否复锻**。Issue 只说"损毁"，本文按不可复锻实现（`StrikeEdge` 对 `Spirit` 无分支）。若能重新加热，需要给一条明确的升温路径。
3. **撞绳算不算锻造面**。**已定（2026-11-05）**：绳不是锻造面，接触 / 下落 / 穿过都不改边态；只有三级以上的弹回按正常红热撞击结算。见 [现行规则 §6-14](../冲刺与对撞-现行规则.md)。
