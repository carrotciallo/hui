# 速度等级：基准与教训

> 结论先写在这里：**以 `Assets/TuningLab` 的脚本版为唯一基准**，其余内容按它移植。
> 不要参考仓库里原有的速度 / 冲刺 / 碰撞实现，也不要参考旧场景里的序列化数值。

---

## 1. 为什么推倒重来

这几轮里，策划和程序在**两套互不兼容的规则**下同时造东西，结果是对不上。

| | 仓库原来 | 现在的基准 |
| --- | --- | --- |
| 挡位的本质 | **状态（buff）**：行为挂一个挡位，速度由挡位给出 | **读数**：速度是因，挡位是 `f(|v|)` |
| 挡位速度 | `{4.7, 15, 18, 21, 24}` 表驱动，间隔无规律 | 每自由下落 **4 格** 升一级 |
| 持续时间 | `Request(tier, duration)`，到点强制回零 | 没有计时，落地/撞墙就掉 |
| 谁给挡位 | 绳子弹、大炮射、撞击击飞 | 只有重力（冲刺和碰撞给的是**速度**） |
| 冲刺 | 水平 3 / 上 6 / 下 3，速度固定一级 | 位移恒定 4 格，速度按进入时的 V前 分三档 |
| 碰撞 | 击飞 + 推挤 3+2+1 | **速度矢量 + 冲刺态整体互换** |

**同一个 `SpeedTier` 枚举，两种语义。** 这不是参数调不调的问题，是因果方向相反。

---

## 2. 当前基准的完整规则

### 等级

- 1 格 = 1 世界单位 = 16 像素
- 每自由下落 `4` 格升一级；`v0..v3` 是零级..三级的**速度上限**，严格超过才进下一级
- 速度上限 = `√(2 · 50 · 4 · (级数+1))` → 20.0 / 28.3 / 34.6 / 40.0

### 冲刺

进入"冲刺态"：位移恒定 **4 格**、不受任何外力、屏蔽输入。

| 进入时的 V前 | 冲刺中速度 | 结束速度 |
| --- | --- | --- |
| 与冲刺方向反向 | Vd1（≈20.12） | **0** |
| 同向且为零级 | Vd1 | **V前** |
| 同向且为非零级 | **V前** | **V前** |

### 碰撞

两人接触 → **速度矢量与冲刺态整体互换**（冲刺态包含剩余距离与结束速度）。

### 其它

- 重力对称 50，跳跃顶点 2.2 格，空中水平方向有 `-g` 空气制动
- 红热：`Vp = 同向 |a²−b²| / 反向 a²+b²`，超过门槛点亮**参与碰撞的那一条边**

## 3. 这几轮做了什么

| 阶段 | 内容 |
| --- | --- |
| 1 | 确认阈值用 v² 表达，避免玩家开根号 |

| 7 | 竖绳：低于二级当墙、二级穿过、三级以上弹回 +1 |

## 4. 教训

**① 两套规则并行开发，代价是全部重做。**
先定一个"唯一基准"，再动手。基准没定之前，任何一边的产出都可能是负资产。

**② 序列化字段会覆盖代码默认值。**
改了常量 → 场景里存的还是旧值 → "改了像没改"。
解决办法是收敛到一个 `GameTuning` 资产，运行时覆盖，改一处全局生效。

**③ 删 `.cs` 文件不清构建缓存，编辑器程序集会编译失败。**
表现为菜单栏整个消失（`[MenuItem]` 没注册）。删文件后要同步清 `Library/Bee`。

**④ 判定阈值和触发条件必须用同一个比较方向。**
冲刺速度正好等于门槛时，触发条件写 `<=` 会导致碰撞逻辑永远不触发。一处 `<=`、一处 `>=`，就会静默失效。

**⑤ 碰撞回调里读到的速度已经被物理解算过。**
要判断"撞击前有多快"，必须在物理步之前缓存一份，否则对撞时读到的是 0。

**⑥ 视觉按"世界单位"写死尺寸时，要抵消父级缩放。**
玩家对象被缩放到 `PlayerSize`，子级的像素图案会缩两次，看起来像"四条边挤成一坨"。

**⑦ 同一份代码在两个工程里各存一份，必然分叉。**
外层工程和仓库各有一份 `TuningLab`，改一边另一边就旧了。
**只保留仓库这一份**，外层工程仅作为临时实验场。

## 5. 移植清单

**已经和基准一致：**

- 挡位推导（`SpeedTierProvider`）
- 冲刺态（`PlayerMotor`）
- 双人碰撞互换
- 玩家三层视觉（`PlayerVisual`）+ 红热
- 竖绳（`LabVerticalRope`，在调试台内）

**还需要按基准移植：**

| 内容 | 现状 | 要做的事 |
| --- | --- | --- |
| 绳子 / 冰面 / 破墙 | 仓库版按旧挡位语义写的 | 对照调试台改写：低挡位当墙、命中挡位穿过或碎裂 |
| 大炮 / 转换器 / 攀爬 / 木筏 | `FormController` 调 `Request/Force` | 改成"给速度"，不再挂状态 |
| 传送门 / 过关门 | 用挡位开门 | 逻辑不用改，但要确认拿到的速度值正确 |
| 关卡 L1 / L2 | 按旧的跳跃距离与推挤摆的 | **重摆**，旧参数已经全部失效 |
