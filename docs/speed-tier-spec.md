# 速度等级 · 规则与数值规格 v0.4

双人 2D 平台解谜。基本单位：**1 格 = 16 × 16 像素**（PPU 16，原生 384×216，1080p 下 5×）。
玩家体积 ≤ 1 格，方块，不旋转。

v0.3 变更：补判定约定、补实测数据、撞机与冲刺规则定稿。
v0.4 变更：充能只认"站地 + 碰队友"（贴墙不算）；水平冲刺加 v1 悬停；门槛由策划自定。

---

## 0. 一句话

**每一级换一个"谁给你速度"。**

| 等级 | 主要来源 | 资源类型 |
| --- | --- | --- |
| v0 | 走、跳、浅落差 | 自己 |
| v1 | 冲刺 | 技能 |
| v2 | 队友撞击 | 队友 |
| v3 | 深坑自由落体 | 世界（重力） |
| v4 | 弹射机关 / 复合 | 世界（机关） |

这条阶梯同时是关卡解锁顺序：每个新房间只提供一种新的速度来源。

## 1. 判定约定（v0.3 新增，容易写错）

从静止下落 `v² = 2gh`，所以门槛可以写成"下落多少格"，程序只算 v²。

**恰好等于门槛 = 进入上一级**（含等号）。

| 折算格数（间距 3） | 等级 |
| --- | --- |
| 2.99 | v0 |
| 3.00 | **v1** |
| 5.99 | v1 |
| 6.00 | **v2** |
| 9.00 | v3 |
| 12.00 | v4 |

为什么必须含等号：**冲刺 = 自由下落一个间距**。冲刺给的速度正好等于门槛值，
若用严格大于，冲刺会永远停在 v0 顶端、涨不了级，整条阶梯的入口就断了。

> 这条早期是反过来的（严格大于），当时是为了让"撞击设定成 6 格"读作 v2。
> 现在撞击改成了"交换 + 升级"，不再有"设定到边界值"的操作，所以改回含等号。

## 2. 等级表与服务它们的速度（g = 50 档）

门槛是**首级 + 等距**生成：`首级 4 格、间距 4 格、4 级` → `4 / 8 / 12 / 16`。

**v0 / v1 / v2 是"零级 / 一级 / 二级速度的分界点"，也就是那一级的最大值。**
恰好等于分界点仍算低一级，必须严格超过。

| 等级 | 折算落差 | 分界速度（g=50） | 谁给你 |
| --- | --- | --- | --- |
| 零级 | 0 – 4 格 | ≤ 20.0（v0） | 走、跳、冲刺 |
| 一级 | 4 – 8 格 | ≤ 28.3（v1） | 超过 4 格的落差 |
| 二级 | 8 – 12 格 | ≤ 34.6（v2） | 超过 8 格的落差 |
| 三级 | 12 – 16 格 | ≤ 40.0（v3） | 超过 12 格的落差 |
| 四级 | > 16 格 | > 40.0 | 机关 |

> 冲刺速度 = 自由下落一个间距 = 4 格 = **恰好等于 v0**，所以冲刺只给位移、不给等级。
> 等级只能靠下落获得。
>
> **相机只有 13.5 格高，三级（16 格）在单屏内不可达**，要么放大相机，要么三级留给竖向滚动。
> `maxFallSpeed` 必须 ≥ 34.6 才能靠下落拿到 v4，默认 36。

## 3. 跳跃和 v0 打架（v0.3 新增，实测）

"跳高 2 格"和"下限 2 格"是同一个数，所以站跳落地正好压在门槛上。

无头自检的实测（`GameJam → Run Speed Tier Self Check`）：

| 重力 g | 站跳 2 格落地速度 | 折算 | 判定 |
| --- | --- | --- | --- |
| 25 | 10.25 | 2.103 格 | v1 |
| 50 | 14.65 | 2.147 格 | v1 |
| 120 | 23.14 | 2.231 格 | v1 |

**降重力没用。** v² 阈值和跳高能量都正比于 g，除掉了；偏差只来自离散积分误差，
方向还反了（重力越大偏差越大）。所以"重力给的速度更少"这条路走不通。

规则：**第一道门槛必须 ≥ 跳高 + 0.3 格。**（0.3 是 2 格跳高的实测偏差，含安全余量）

三个可选解：

| 方案 | 跳高 | 门槛 | 代价 |
| --- | --- | --- | --- |
| A | 2.2 | 2.5 / 4.5 / 6.5 / 8.5 | 门槛不再是整格 |
| B | 1.7 | 2 / 4 / 6 / 8 | 跳不上 2 格台，关卡只能用 1 格台阶 |
| **C（推荐）** | 2.2 | **3 / 5 / 7 / 9** | 关卡要更深，v4 需要 9 格落差 |

C 是唯一既保住整格、又保住 2 格间距的解。代价是每个等级更"贵"，
相机至少要 12 格高，或者做竖向滚动。

## 4. 规则（v0.3 定稿部分）

| 编号 | 规则 |
| --- | --- |
| R1 | 等级由合速度 v² 判定，不分横竖轴 |
| R2 | 冲刺是**四方向**的：速度被**覆盖**成「方向 × 冲刺初速」。水平与竖直共用同一个初速 |
| R2a | 冲刺 = **冲刺态**：位移恒定、不受任何外力、屏蔽输入。速度由进入时的 V前 分三档（反向→Vd1/结束0；零级同向→Vd1/结束V前；非零级同向→V前/结束V前） |
| R2b | **向下冲刺只允许在空中**。站在地面（含队友头顶）按下冲刺无效，且不消耗充能 |
| R2a | 若当前速度在冲刺方向上的投影已 ≥ v1，则保持不变（不降级） |
| R2b | **只有水平冲刺**在速度仍处于 v1 区间时关闭重力（悬停）；一旦离开 v1（减速、撞停、被撞到 v2+）立刻恢复重力。竖直冲刺重力照常 |
| R3 | 冲刺充能：只存一次。**站在地面上、或碰到另一名玩家任意一面**给这次充能上弦；**贴墙、顶天花板不算**。上弦后计时自行走完，离地也继续回复；用掉后需重新接触才能再上弦 |
| R4 | 双方沿碰撞轴的速度都在 v0 以内 → **普通物理**，不做任何特殊处理 |
| R5 | 只要**有一方超过 v0** → 进入特殊判定，**红热与加速可以同时发生** |
| R5a | **红热**：`Vp = 同向 \|va²−vb²\|，反向 va²+vb²`；`Vp ≥ v2 门槛的 v²` → **只有 A（大框）**参与碰撞的那条边进入**红热态 1** |
| R5b | 红热态 1 超时回常态；**热态 1 期间再次触发 → 红热态 2（永久）**；状态变化外抛 `EdgeStateChanged` |
| R5c | **动量交换**：双方**速度矢量整体互换**，并且**冲刺态可以一起交出去**（方向、速度、剩余距离原封不动），接手的人从同一位置继续冲 |
| R6 | 碰撞只有水平面和竖直面，永不产生斜向 |

> 所有判定都吃**碰撞前**的速度：`OnCollisionEnter2D` 触发时 `rb.linearVelocity` 已经被解算改掉，
> 对撞时可能已经是 0。代码里用 `lastFixedVelocity` / `PreImpactVelocity`。
>
> `+1 级` 是整套系统里**唯一凭空产生的能量**：不消耗高度、不守恒。
| R7 | v4 不可由玩家自制，只能由关卡机关提供 |

**R2 必须是"覆盖"，不能是"叠加"。**
四方向冲刺之后，如果保留垂直分量，下落 v2 的人向右冲刺会得到
`√(19.4² + 20²) = 27.9` ≈ 7.8 格 → **凭空变成 v3**。整条阶梯当场作废。
覆盖会把垂直分量清零，`|v|` 严格等于冲刺速度，等级不会跳。

**代价（必须知道）**：向上冲刺 = 获得 19.4²/100 = **3.76 格的免费高度**，
落地时又原封不动换回速度。所以"上冲 + 掉坑"可以间接造出 v3——
这是物理，不是 bug，但关卡设计得把它算进去。

**R2b 的两个推论（Play 验证已确认）**：
- 水平冲刺速度 19.4 = 0.97 × v1/v2 临界（4 格），落在 v1 区间，因此正常情况下一路悬停、不白嫖 v2。
- 悬停没有时限（`空中制动 = 0`）。它会一直滑到反向输入、撞墙、或被打到 v2+ 为止。
  如果要做时限，只能另加规则；目前的设计就是"滑到停为止"。

## 5. 自检输出（可复现）

```
=== 1. 起跳初速 → 实际顶点 ===
  g=50 h=2.00 v0=14.65 apex=2.002  OK
=== 2. 格 ↔ 速度 往返 ===
  2.0 格 → v=14.14 → 2.000 格  OK
=== 3. 等级边界 ===
  2.00 格 → v0
  6.00 格 → v2
```

起跳初速用了补偿公式（半隐式欧拉会让顶点比连续解低 `v0·dt/2`），
否则"跳高 2 格"实际只有 1.86 格，上不去 2 格台。

## 6. 关卡语法

- **可达落差 = 造币厂。** 平台布局决定能掉多深，天花板决定能跳多高。
- **每个资源的价值 = 另一种资源缺席。** 浅房间只剩冲刺；只有一人能到的地方只剩撞击。
- **别做"三种手段都可行"的房间**，那等于没出题。
- **双人：撞击是唯一能把等级从一个人搬到另一个人的方式。**
- **不要做**：计时器、速度衰减、需要精确操作才能拿满的等级。

## 7. 仍然开放的岔路：实时态 vs 定格态

v0.3 没有解决这一条，因为它决定整套玩法。

- **实时**（当前描述）：等级 = 此刻速度。诚实、拖尾直接对应。
  代价是窗口极短——落地或撞墙立刻归零，双人同键盘要卡同一帧。
- **定格**：等级 = 本次腾空内的最高值，落地保留到被用掉。可规划、可商量。
  代价是显示与物理脱钩，要另做一条视觉通道。

demo 里落地瞬间速度归零、"净落差"保留——这个现象就是分歧点。
**空中制动 = 0 时，速度本来就能一直保持着飞**，所以空中其实不需要额外的锁存系统；
真正的问题只在"落地之后还能不能留着"。

## 8. 验收标准

- [ ] 平地起跳落地，等级为 v0（需要按 §3 抬门槛或压跳高）
- [x] 冲刺后折算 3.76 格 → v1，颜色为黄（无头 Play 已验）
- [ ] 被 ≥v1 队友撞击后折算 6.00 格 → **v2**（不是 v3）
- [ ] 撞击者不掉速
- [ ] 从 8 格高台落下 → v3
- [ ] 站立 10 秒，等级不变
- [ ] 改变 g 之后，所有"格"门槛不变（只变绝对速度）
- [ ] 撞击不产生斜向速度
- [x] 水平冲刺在 v1 区间内悬停（不受重力），竖直冲刺重力照常（无头 Play 已验）
- [x] 贴墙 / 顶天花板不充能；站地或碰队友才充能（无头 Play 已验）
