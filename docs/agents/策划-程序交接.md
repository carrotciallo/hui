# 策划 → 程序 · 交接手册

> 适用于本仓库：Unity 6000.6.4f1，规则基准在 `Project/nameless/Assets/TuningLab`，关卡数据在 `Assets/TuningLab/Level`，Issue 在 GitHub `sfher/hui`。

## 0. 一句话

**策划交付可观测的规则，程序交付可复现的读数。中间不靠口述。**

当前唯一实现基准是 Tuning Lab；正式关卡从 Tuning Lab 派生，预览与 Play 共用 `LabLevel.Build`。

## 1. 谁定什么

| 内容 | 负责方 | 产物 |
| --- | --- | --- |
| 玩法规则和边界 | 策划 + 程序共同确认 | Issue + 必要时 ADR |
| 数值 | 策划在 Tuning Lab 调整并定稿 | Issue 定稿评论 + 基准配置 |
| 实现方式 | 程序 | 代码 + PR |
| 读数和验收 | 双方 | SelfCheck / PlayCheck / PlayMode 规格 / 手工清单 |

## 2. 一条机制需求的四件套

```text
触发：什么条件下发生，明确 >=、> 和相等边界。
效果：用格、速度、秒描述，禁止只写形容词。
读数：在哪个 HUD、日志或自检结果里能观察。
反例：什么情况下必须不发生。
```

补充影响范围：涉及哪些关卡、机关、数据字段、编辑器工具和文档。

## 3. 交接流程

1. **立案**：Issue 写完整四件套和影响范围。
2. **原型**：先在 Tuning Lab 中实现可调版本。
3. **定稿**：Issue 写出唯一数字和边界。
4. **移植**：接入 `LabLevelData` / `LabLevel.Build` 或正式运行时组件。
5. **验收**：运行 SelfCheck、PlayCheck，必要时补手工回归；结果写入 PR。
6. **同步文档**：规则变化同步当前基准导航、机制文档和 ADR；旧规则明确标记历史。

## 4. 需求语言

| 不要写 | 应写成 |
| --- | --- |
| 撞飞出去 | 沿碰撞轴速度 = X，位移 = Y，持续 = Z |
| 手感太飘 | 地面加速度从 X 调到 Y，其余不变 |
| 能穿过去 | 指定碰撞体、触发条件和离开后的恢复行为 |
| 跳不上这个台 | 台高 X 格，跳高 Y 格，实测结果为可达/不可达 |

## 5. Issue 模板

```md
## 目标

## 规则

- 触发：
- 效果：
- 读数：
- 反例：

## 影响范围

## 待拍板

## 不做
```

## 6. PR 验收模板

```md
## 改了什么

## 读数

| 项 | 期望 | 实测 |
| --- | --- | --- |

## 测试

## 文档

- [ ] 当前基准已同步
- [ ] 过期规则已标记
```

规则冲突时先停手，明确唯一基准，再继续开发；不要让策划案、代码和关卡各自维护一套规则。
