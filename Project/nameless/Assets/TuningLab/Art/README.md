# Issue #26 selected pixel art

用户选定组合：第一组工业场景物件 + 第二组蓝/红几何人物。素材由 OpenAI 内置 image generation 工具生成候选图，经用户选择后裁切、最近邻采样和有限调色板整理；不是第三方素材包。

## 规格与分层

- PNG RGBA，原生 16 px/格；全套共 44 种不透明颜色，文件 alpha 仅 0/255，无渐变或羽化。
- Unity：PPU 16、Point、Full Rect、中心 pivot、无 mipmap、无压缩。`LabArtImporter` 固定这些设置。
- 方块 16×16；门 16×48；传送点及重生标记 48×48；刺 16×6 / 6×16；竖绳 6×16、横绳 16×4，均沿用当前规则尺寸。
- 人物使用第二组的独立部件遮罩：A 上/下 14×2、左/右 2×10，组合后外框 14×14、内框 10×10；B 本体 10×10。角色 PNG 均为 16×16 透明画布，代码按原像素裁出中心部件并定位，不缩放像素，也不把全部状态烘成整图。
- 角色四边常态/红热/灵体仍独立染色；2×2 纯白朝向眼睛、速度外圈继续独立绘制，13 种形态组合不变。

## 接入范围

`LabLevel.Build` 与 `TuningLab` 共用显示资源；无需逐一修改场景文件。覆盖所有现有正式关卡、关卡预览、测试房和运行时重建/重置出的对象：地形、隐藏墙、横竖绳、钥匙、门、冰、岩浆、四向刺、重生旗、三态传送门、召回道具，以及玩家和幻影。

地形与横绳逐格重复，不把一个像素图拉成长平台。隐藏墙采用同一地形图，揭示时同步透明度。冰块保留原有分组边框；重生点激活时旗帜变绿；门与传送点按原游戏状态换图。

`LabArtPresenter` 只处理显示，保留原渲染器供状态逻辑读写，同步隐藏/透明度/排序/翻转，不改变碰撞、关卡坐标或规则。资源缺失时保留原来的程序绘制作为回退。

木箱、钢板、熔岩表面、出生台图标一并保存在资源目录，当前规则没有相应可放置实体，因此不新增机关或装饰物来使用这些图。重生旗复用同一轮廓，通过激活色区分状态。

可摆放的纯视觉像素画放在 `Resources/PixelArt/`，由关卡编辑器的「像素画」工具写入 `LabLevelData`。素材使用相同的 16 PPU / Point / 无压缩导入规则；放置时可选择 1×1、2×2 等整数格占地，并设置排序层。像素画不生成碰撞体，也不参与玩法判定。

## 生成提示词摘要

工业场景：2D 正视像素平台游戏，暗紫金属/石块、青色冷光描边、金色绳与门锁；包含地形拼块、冰、裂纹岩浆、四向刺、钥匙、门、三态传送门、重生与召回标志。无文字，无场景透视。

人物：蓝色 14×14 空心框 A、珊瑚红 10×10 方块 B，2 px 框边，四边独立，白色朝向眼睛；常态、红热、灵体和形态组合使用一致几何。第二组石质环境未选用。

原始候选图不是生产用像素尺寸；本目录 PNG 是整理后的运行时素材，不直接导入原始大图。

验证方法：Unity 6000.6.4f1，`LabArtSceneCheck.RunBatch` 检查所有正式场景预览及导入参数；PlayMode 中 `LabArtTests` 检查门状态/重置/显隐以及合并地形尺寸，再运行现有玩法回归测试。
